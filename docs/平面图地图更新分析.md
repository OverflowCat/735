## 地图交互与绘制

1. 厂区总览显示五个区域的名称、设备数量和报警摘要。点击建筑进入室内图；建筑应支持键盘操作，并与设备点击区分开。
2. 室内图保留墙体、门、楼梯、设备轮廓和关键房间名称，裁掉标题框及无关留白。水冶厂显示楼层切换和返回总览入口。
3. 优先复用原图线条生成 SVG；若原图字体或导出质量不稳定，可离线输出足够分辨率的 PNG/WebP。底图放在 Vite 的 `public/floorplans/`，运行时无需 PDF 阅读器。无需使用 AI 重绘工程图。
4. 原图的红圈、γ 编号和氡编号是安装标注，不是报警状态。发布用底图应将这些静态点位标注去掉，由前端统一绘制；保留原 PDF 供核对。若无法可靠清除，则应按图纸追描简化的墙体和设施，避免双重标注。
5. 同一安装位置的 γ 与氡共用定位锚点，标签分别显示剂量率和浓度，并能分别打开对应设备抽屉。为防标签重叠，可以偏移显示标签并用引线连接，物理锚点不应随标签偏移。
6. 展示图纸编号与资产号，避免把 `gamma_12` 当成现场安装编号；读数旁显示对应单位。无数据点位保留图标并标“未上报”或“未接入”，只有获得状态依据后才标为离线。
7. 继续通过显式二维编辑模式移动点位；切换楼层或区域时退出放置与拖动状态，清空编辑选中和当前撤销栈，避免对另一张图应用旧坐标。

图纸上的位置差异应落实到局部图：C19 的 γ04 在左下、γ28 在右上；过滤厂房 γ24 在左下、γ18 在右下、γ29 在右上；C35 的 γ03 所在下方区域不能挤进当前顶面的同一排位置。

## 坐标与数据组织

每张室内图设置稳定 `mapId`，例如 `c19`、`c35`、`c3`、`filter`、`hydromet-f1` 至 `hydromet-f4`。厂区总览单独使用 `site`。图纸尺寸和方向独立，不强行挤进总览的 1200×800 画布。

建议将固定图纸配置、安装台账和实时设备读数分开：

- 图纸配置：`id`、名称、所属建筑、楼层、底图、坐标范围、图纸版本。
- 安装台账：资产号、当前后端 `deviceId`、`mapId`、图纸坐标；氡记录关联的安装位置或 γ 资产。
- 运行状态：当前地图、当前楼层、选择、编辑覆盖、撤销记录，通过现有 state mutator 更新。

初次录点时，在去掉留白和标题的有效图框内取圆圈中心。若裁剪框左上角为 `(x0, y0)`、宽高为 `(w, h)`，圆心为 `(px, py)`，可保存归一化坐标：

```text
u = (px - x0) / w
v = (py - y0) / h
x = u * scene.width
y = v * scene.height
```

坐标原点统一在左上角，向右、向下为正；若直接读取 PDF 原生坐标，则先转换其坐标方向并应用页面旋转。选定底图裁剪框后再录点，替换底图时通过版本和变换迁移坐标。捕捉网格应允许关闭，图纸原始点位无需强行取整到 10px。

二维和三维沿用同一份图内坐标。第一步三维继续提供厂区示意，室内图以二维为主；若后续提供室内三维，应从同一份局部几何和点位生成，并显式配置示意高度，不能从这些 PDF 推断实际楼层高度。

## 现有实现需要处理的具体问题

| 位置 | 当前行为 | 更新要求 |
| --- | --- | --- |
| `src/lib/data/mock/scene.ts` | 五栋示意建筑，水冶 20 台 γ 为 5×4 网格 | 保留总览，室内点位按图纸重建 |
| `src/lib/types/scene.ts` | 单场景，点位只有设备 ID 和 x/y 等字段 | 增加图纸配置与多场景关联，明确资产号映射 |
| `src/lib/data/mock/devices.ts` | 缺少 `2026012905`、`2026012917`、`radon-37`、`radon-36` | 补安装台账并提供无数据占位，不能虚构测值 |
| `FactoryMap.svelte` | 只有找到实时 / mock 设备才绘制点位 | 从安装台账绘制全部位置，再叠加读数 |
| `FactoryMap.svelte::svgPoint` | 用元素外框宽高换算坐标 | 改为 `getScreenCTM().inverse()` 转换屏幕点，避免 SVG 等比缩放留白造成偏移 |
| `FactoryMap.svelte` | 初始 viewBox 固定 1200×800 | 随地图尺寸适配，切换时重置或恢复对应视口 |
| `MapPage.svelte` | 仅二维 / 三维切换 | 加区域导航、楼层选择、返回总览 |
| `app-state.svelte.ts` | 仅一份 scene、localStorage 和撤销栈 | 分地图保存编辑覆盖和版本，隔离编辑上下文 |
| `resetPlacements()` | 恢复总览 mock 的全部点位 | 改为恢复当前地图对应版本的默认点位 |
| `loadScene()` | 非空远端 objects 覆盖本地场景，objects 为空则忽略 | 按格式版本加载；底图加点位的地图即使没有 objects 也应有效 |

当前场景已有上述四个缺失设备的 placement，但渲染时受 `{#if device}` 限制，所以会消失。生产 API 同样可能只返回已上报设备，单独补 mock 不能解决这个问题，需要把安装台账与实时设备列表合并。

地图保存还有一项现有不兼容：Rust `backend/src/model.rs` 的 `SceneObject` 要求矩形的 x/y/width/height，前端 C35 使用多边形；Rust 也没有前端的 `shape`、`points`、底图、多地图、`labelStyle` 等字段。沿用现有 PUT 完整场景可能反序列化失败或丢失字段，不能只在前端类型上加字段便认为已支持远端保存。

前端第一阶段可以使用打包的图纸及默认点位，并按地图将编辑覆盖保存在带版本的 localStorage 中。旧 `/scene` 只按已支持的旧格式使用，不能覆盖新版室内图配置。若要求多终端共享编辑结果，再同步调整 Rust 的场景模型与加载 / 保存逻辑；此处属于地图配置，不改变 `protocol.typ` 的监测数据上报语义。

## 建议实施顺序与验收

1. 建立上表的资产台账，核对生产旧设备 ID 与 IP 的映射，确定八张室内底图及裁剪框。
2. 先完成水冶一楼作为样板：12 个 γ、3 个氡的位置、读数、单位、缺数据状态和设备抽屉均正确。
3. 加楼层 / 建筑切换，扩展到全部八张室内图；总览改为区域摘要，避免将所有楼层设备堆在同一屋顶。
4. 完成按地图的编辑、重置、撤销和版本迁移，再决定是否接入远端保存。

验收应核对 30 个 γ 和 10 个氡，每个逻辑设备恰好对应一处室内位置；总览的区域摘要不计作新增安装点。特别检查 γ16 → `gamma_12`、γ21 → `gamma_15`，以及全部 10 组 γ / 氡配对。对每张底图检查角点和中心的点击 / 拖动，覆盖容器比例变化、缩放与平移。还应确认换图后的撤销、刷新后的保存、旧缓存迁移、无数据点位和实际报警不会被底图红色标注混淆。

实施代码后运行项目的类型检查与生产构建，并对多地图切换及持久化做针对性验证。本次仅新增分析文档，未运行应用构建。
